## ⚠️ INSTRUCTIONS FOR THE AI READING THIS FILE (IDE Assistant / Claude in IDE)

**You are the coding agent. This document is your task specification. Read it fully before writing any code.**

You must operate as a **self-correcting build loop**. Your job is not "write code once and stop." Your job is to keep building and fixing **until the current milestone's Acceptance Checklist passes 100%**. Follow these directives:

1. **Work one milestone at a time, in order (1 → 2 → 3).** Do not start Milestone 2 until Milestone 1's checklist fully passes. Do not start Milestone 3 until Milestone 2's fully passes.
2. **After each build pass, self-verify against that milestone's Acceptance Checklist.** Go through every single item. For each, state PASS or FAIL with a one-line reason.
3. **If ANY item FAILS: fix it, then re-run the ENTIRE checklist from the top** — not just the item you fixed. A fix often breaks something else. Repeat this loop until every item is PASS.
4. **Do not declare a milestone "done" until 100% of its checklist is PASS.** "Looks fine" is not done. Every box must be ticked with evidence.
5. **Respect the hard rules per milestone** (no database, no Phase 2 code, no custom domain, credentials only from env vars). If you catch yourself about to violate one, stop and correct.
6. **Stay in Developer 1 scope only** (pages, navigation, content, Apply Now / job-seeker flow). Do not build Developer 2's work (images, animation ownership, Request Manpower flow logic, deployment ownership) unless this doc explicitly assigns it here.
7. **At the end of each milestone, output:** (a) the full checklist with PASS/FAIL, (b) the list of files you created/changed, (c) any item still blocked on human-provided data (e.g. SMTP creds), and (d) the exact git commands the human should run for that milestone (from Part 5).
8. **Never invent client data.** Where real values are missing (SMTP creds, business email, WhatsApp number, phone, address, etc.), leave clearly-labeled empty typed slots and report them as blockers — do not fill them with fake values.

**Your loop exit condition, restated:** a milestone is complete only when every line in its Acceptance Checklist is PASS and no hard rule is violated. Until then, keep looping.

## PART 1 — THE LOOP PROTOCOL (the AI must follow this)

**Rule: the milestone does not finish building until it matches the expected result in the documents.** Enforced as a loop the IDE AI runs on itself:

```
FOR each milestone (1 → 2 → 3):
    1. BUILD    → implement every task in the milestone's Dev 1 list
    2. VERIFY   → self-check EVERY item in the milestone's Acceptance Checklist,
                  marking each PASS or FAIL with a reason
    3. IF any item FAILS:
           → fix it
           → GO BACK to step 2 and re-run the FULL checklist (not just the fix)
    4. IF all items PASS and no hard rule is violated:
           → output the checklist result + changed files + blockers + git commands
           → the human commits + pushes to the milestone branch, merges to main
           → only THEN move to the next milestone
```

**Loop exit condition = 100% of that milestone's Acceptance Checklist passes.** Not "looks fine." Every box ticked with evidence. One failure restarts verification from the top, because a fix in one place often breaks another.

### WHERE SMTP / NODEMAILER GOES (your manual setup map)

```
project-root/
├── .env.local            ← YOU PASTE SMTP CREDS HERE (manual, never committed)
├── .gitignore            ← must contain .env.local  (verify this!)
├── app/
│   └── api/
│       └── apply/
│           └── route.ts  ← Nodemailer API route lives here (IDE AI writes this)
└── components/
    └── flows/
        └── ApplyNowModal ← the pop-up; calls /api/apply for the email option

**The ONLY manual credential step — your `.env.local` file:**
```
SMTP_HOST=your.smtp.host
SMTP_PORT=587
SMTP_USER=your_smtp_username
SMTP_PASS=your_smtp_password
SMTP_FROM="Taoohan Careers <noreply@yourdomain.com>"

Rules:

- On Vercel later: paste the same keys into **Vercel → Project → Settings → Environment Variables** (manual, one time).
- WhatsApp routing needs NO creds — just the client's WhatsApp number, which you can put in your content/config file.
