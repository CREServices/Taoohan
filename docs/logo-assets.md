# Brand logo assets

The client supplies the logo as three flattened PNGs in `public/logo/`:

| Supplied file      | What it is                            | Ground baked in |
| ------------------ | ------------------------------------- | --------------- |
| `taoohan-dark.png` | Full wordmark, dark lettering         | white           |
| `logo-dark.png`    | Two-person mark only                  | white           |
| `logo-white.png`   | Two-person mark, inverse treatment    | `#26332A`       |

All three are **opaque** — the background is painted into the file. Used as-is
they render a pale rectangle on the footer's inverse band and a white box
behind every page watermark, so they are not wired up directly.

## Deriving the site assets

```
node scripts/build-logo-assets.mjs
```

That reads the three supplied files and writes four transparent, trimmed
assets, which are what `LOGOS` in `src/config/images.ts` actually points at:

| Derived file                     | Used by                          |
| -------------------------------- | -------------------------------- |
| `taoohan-wordmark.png`           | header (`Logo variant="onLight"`) |
| `taoohan-wordmark-inverse.png`   | footer (`Logo variant="onDark"`)  |
| `taoohan-mark.png`               | page watermark (`.brand-watermark`) |
| `taoohan-mark-inverse.png`       | browser icon (`src/app/icon.png`) |

### How it works

The artwork is flat vector fill in exactly four colours, so each pixel can be
un-composited back to real alpha. For a pixel `P` painted over ground `B`,
`P = A·C + (1 − A)·B`. The script picks `C` from the known palette by nearest
distance to the segment `[B, C]`, then recovers `A` from how far along that
segment `P` sits — which keeps anti-aliased edges smooth instead of producing
the hard fringe a colour-key would.

The palette is the locked brand palette from `src/app/globals.css`, and the
supplied files match it exactly: `#26332A` (`--color-surface-inverse`),
`#5FAF73` (`--color-brand-500`), `#CCE3C3` (`--color-brand-200`).

The inverse wordmark is the same pass with one remap — `#26332A → #FFFFFF`,
greens untouched — which reproduces the client's own dark-background
treatment from `logo-white.png` for the full wordmark, which they did not
supply.

## Browser icon

`src/app/icon.png` and `src/app/apple-icon.png` are generated by
`scripts/build-icons.mjs` from `taoohan-mark-inverse.png`, on the brand's dark
ground rather than on transparency: the mark's left ring is `#26332A`, which
all but disappears against a dark browser tab strip. On the dark tile both
rings stay legible at 16px.

## If a replacement file arrives

Drop it into `public/logo/`, re-run the scripts, and update the pixel
dimensions in `LOGOS`. Do not hand-crop — the two wordmark variants must stay
at the same crop or a single CSS height renders header and footer at
different sizes.
